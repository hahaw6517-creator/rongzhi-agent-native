# 中小微与科创企业融资决策闭环

本版聚焦制造类、软件与信息技术类中小微及科创企业。企业服务类型由使用者选择，不构成法定中小微划型、科技型中小企业入库或高新技术认证。其他行业明确提示尚未配置专门模型。

## 用户只需提供什么

企业名称、完整年度、行业、地区、报表来源，以及13项本期报表原值：资产总计、负债合计、流动资产、流动负债、短期借款、长期借款、一年内到期非流动负债、营业收入、营业成本、净利润、经营现金流净额、购建长期资产支付现金、期末现金及现金等价物。

网站另填外部借款金额、用途、期限和企业服务类型。外部借款额是扣除自行安排资金后还想向外借的钱，不重复减去账上现金。用途包括周转、备货、设备购置和研发周转。金额不是公开报表事实，单独保存在需求快照中。

两期应收、存货、预付、应付、预收和合同负债可选。全部齐全才计算经营性净营运资本变化及增长占款；缺失不补0，改用最近完整年度经营现金流保持不变的情景，并标明不能进行细分需求外推。利息附注未公开时，用借款余额×假设利率估算；不得称为合同本息。

## 12个真实工具

核验财报 → 计算指标 → 推导历史现金需求参照 → 风险筛查 → 检索专业产品知识 → 期限压力对照 → 匹配产品方向 → 约束优化 → 行业地区近期研究 → 独立还款表验证 → 复审原需求并重求替代方案 → 报告交付。

AI模式使用项目原API，由模型选择工具、读取观察结果；工具依赖在服务端约束。模型不能修改财报、调用参数或金额。行业地区专家提示词收到需求筛选、真实产品登记、财务结果和近期来源，引用必须通过白名单校验。金融金额由Python求解，产品资格不由大模型推定。

## 金融模型

财务指标包括流动比率、资产负债率、毛利率、净利率、经营现金率及可计算的周转指标。制造类优先看库存、应收、现金周转周期和设备用途；软件信息技术优先看回款、利润兑现现金、研发支出的偿付压力。缺少对应科目时显示未计算原因。

还款现金代理=下一年度经营净现金情景－历史资本开支×资本开支倍数×维持性占比。存量本息压力代理=短期借款＋一年内到期非流动负债＋历史利息或利息情景。此口径保守保留存量压力，不表示合同到期日或真实DSCR。

新增还款预算=max(0,压力后的还款现金代理÷安全倍数－存量本息压力代理)。

新增负债边界=max(0,报表总资产×设定负债率上限－报表总负债)。保持报表资产基数不变，不假定研发费用或新借款一定形成新增资产。65%负债率、1.2倍覆盖、20%现金下降及加息1个百分点均为可调整的演示情景，不是银行统一标准或市场预测。

四变量线性规划通过顶点枚举求解：先最大化可配置金额，再最小化假设全期限利息，或最小化还款峰值。约束包含用户需求、公开产品上限（若公开）、用途、期限、杠杆和现金压力。产品未公布额度时只有财务预算，不编造额度；企业准入未知时只输出条件式拟申请方案。

未知还款方式的周转产品保守按到期一次还本付息，计入本金和全期限利息集中支付的最重12个月；有分期还本依据的渠道使用按月等额本金情景。所有渠道最重12个月保守合计，再加存量压力，不把多年期贷款只算第一年利息，也不假定能够续贷。实际还款方式、利率、费用须由受理机构确认。

## 需求复审与持续调整

先检验原金额、用途、期限、杠杆和还款压力。需求超过历史推导缺口，只提示解释新订单或新项目，不仅凭财报断言新增需求不合理。

原需求无法在约束下覆盖时，另外对支持的更长期限重新求解，比较可配置金额及利息，选出通过独立验证的调整方案。明确列出新金额、各渠道、最长还款期及需要缩减或延后的支出。若现有债务已不能通过现金压力，报告明确“暂无通过验证的新增债务方案”，不编造股权资金、补贴或新贷款补缺口。

验证器独立逐月展开还款表，检查最重12个月本息、资金加总、需求、杠杆、官方产品范围及期限，不复用优化器的还款系数。替代方案再次验证，并在工具证据中保存完整方案及验证结果。

持续交互默认采用方案页和报告旁的专业对话框。原API理解问题后选择读取分析、指标解释、方案重算、采用已验证建议、市场更新、历史版本比较等工具。用户可直接说“改成借60万元、36个月还完”，无需回工作台填写参数。手动表单只作为折叠的高级入口。

对话仅允许改变用户明确提出的借款需求或模型假设，不允许改变财报原值、凭空增加授信或认证。服务器独立验证元／万元／亿元和年／月换算；金额、期限不清楚时追问，原需求与建议不同时，相对增减还须澄清基准。原API提供解释，Python生成数值卡、比较表和验证记录；正文引用的金额、期限、百分比和倍数按单位核对已有工具结果。原需求期限和原推荐期限分列，避免混淆比较基准。

近期问题必须实际执行市场研究工具；未取得合格近期正文时明确资料不足，不把历史解释或模型常识包装成最新信息。重算和市场更新都重新运行财务模型、优化、压力验证及需求复审，保留原财报、旧结果、父版本和金额差值。历史资料沿用时重新检查时效；不为体现时效性强行改金额。

每轮成功的调整与对话记录原子保存。API失败或必要工具未完成时不保存草稿方案；若只有模型文字的数值、引用或格式未通过校验，则丢弃这些文字，明确标识为服务器金融工具生成的结论，并保留真实重算的情景版本，绝不冒充模型解释已通过核验。旧报告不覆盖。原生版按浏览器会话隔离，最多保留最近20轮对话和12个分析版本；原报告可回查，版本对比只读取同企业同财报快照。浏览器刷新后可以恢复对话。Streamlit版使用当前浏览器会话保存。

## 页面分工

工作台用于填需求和启动任务。方案页用于审查原需求，通过对话执行调整及回看版本。报告页突出本次问题、关键指标、需求匹配、策略、风险和最终建议，并直接支持追问与重算；桌面版对话面板在报告旁固定显示，手机上优先显示对话入口。详细复算与来源默认折叠。融资组合、风险分析、方案比较分别突出渠道金额、现金风险及临界点、真实重求的不同策略；相同方案合并展示。

费用尚未纳入数值优化，未知费用不代表免费。年度代理现金无法验证季节性和月内资金断裂。没有财报内的征信、税务、评分、抵押权及首付款条件，不能宣称企业通过银行准入或实际获得授信。
