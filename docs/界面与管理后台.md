# 界面与管理后台说明

本仓库为原生网站（Starlette + 原生 JS 单页应用，无前端框架）。本文档说明前台界面结构、管理后台布局、模型配置的复用方式与主题化组件约定，供后续维护与二次开发参照。

## 一、前台界面结构

前台入口为 `/`（登录后进入分析工作台）。左侧边栏固定为 **6 项导航 + 底部企业卡片**，排列顺序即业务流水线的执行顺序：

| 导航项 | 路由 | 对应流水线阶段 | 页面核心内容 |
| --- | --- | --- | --- |
| 分析工作台 | `/workspace` | 入口 | 选择演示案例或上传财报，发起融资分析任务 |
| 企业与数据 | `/company` | 数据核验 | 三年财报录入与勾稽核验，确认一年期融资需求 |
| 财务分析 | `/analysis` | 指标与预测 | 指标计算、五块诊断、下一年现金预测 |
| 融资决策 | `/solutions` | 组合优化 | 三类贷款筛选结果、MIP+CVaR 组合金额与依据 |
| 风险评估 | `/risk` | 情景检验 | 六情景压力测试、逆向压力边界、独立约束验证 |
| 分析报告 | `/delivery` | 交付 | 报告全文、Word 下载、右侧决策对话（调参） |

侧边栏设计约定：

- 导航即流程：6 项对应「数据 → 分析 → 决策 → 验证 → 报告」，每一步在该页展示自己的输入、输出与证据，评审时可逐页走查。
- 侧边栏仅保留 Logo、6 项导航、企业卡片（当前分析企业名称 + 报告期徽标），不再放置标语区或重复的步骤横条。
- 桌面端侧边栏可经左上角按钮收起为 68px 图标窄条（对标主流 AI 工作台，状态持久化），移动端（≤760px）收纳为抽屉，配合遮罩层交互。

## 二、管理后台

入口为 `/admin.html`，仅当服务器设置了 `ADMIN_PASSWORD` 时可用（未设置时登录返回 503）。

后台采用**侧边栏布局**（与前台视觉语言一致）：左侧为品牌区 + 功能导航，右侧为内容区。当前包含三个板块：

| 板块 | 功能 |
| --- | --- |
| 平台托管模型 | 维护平台托管的 OpenAI 兼容模型配置：新增、编辑（API Key 留空表示保留原值）、启用/停用、连通性测试、删除 |
| 供应商管理 | 维护 AI 供应商注册表（供模型配置的供应商宫格选择），含图标与排序 |
| 用户管理 | 查看全部注册账户（角色、状态、历史分析数量、注册/最近登录时间）；重置密码（主题化输入弹窗）、禁用/启用（禁用立即生效，已签发 token 一并拦截）、删除（级联清理该账户的历史分析、自配模型与问答记录）；管理员不能禁用或删除自己 |

后台侧边栏与前台一致：桌面端可经左上角按钮收起为图标窄条（独立持久化键 `finbridge_admin_sb`），移动端为抽屉导航。

删除等破坏性操作统一使用主题化确认弹窗（见下文），不使用浏览器原生 `confirm`。

## 三、模型配置：前后台复用同一套组件

前台「模型设置」弹窗与后台「平台托管模型」表单**复用同一套共享组件**（`web/model-picker.js`），保证字段、交互和配置规则完全一致：

- 供应商宫格选择（含图标）、接口类型（协议）下拉、接口地址、模型 ID、显示名、API Key 输入。
- 数据收集由 `mpCollect()` 统一完成，前后台提交同一套字段（含 `provider`）。
- 后端落库于 `ai_platform_model` 表，`provider` 列在建表与旧库迁移（`PRAGMA table_info` 检查 + `ALTER TABLE ADD COLUMN`）中均会补齐。

模型调用解析优先级（`src/finbridge/model_resolver.py`）：**用户自配（会话级）→ 平台托管（后台启用项）→ 环境变量**。密钥一律 Fernet 加密落库，接口仅返回掩码。

## 四、主题化组件约定

所有浏览器原生控件必须替换为符合主题风格的自定义组件，实现于 `web/theme-ui.js`：

| 组件 | 用途 | 说明 |
| --- | --- | --- |
| `uiSelect` | 下拉选择 | 触发器 + 浮层列表 + hidden input 携带值，兼容 `FormData` 与 `[name=x].value` 读取；options 支持字符串、`[value,label]` 数组与对象三种形式 |
| `uiConfirm` | 确认弹窗 | 返回 Promise；danger 场景默认焦点在取消按钮 |
| `uiAlert` | 提示弹窗 | 返回 Promise |

实现要点（踩坑记录，改动前必读）：

1. 应用脚本在 `.dialog/.drawer` 容器上注册了 `stopPropagation()` 拦截冒泡，因此主题组件的 `document` 级点击委托必须使用**捕获阶段**（`addEventListener(..., true)`），否则弹窗内组件点击无效。
2. `uiSelect` 的选项归一化必须同时处理字符串、数组、对象三种入参，否则会出现选项渲染为空的问题。
3. `mpCollect(scope)` 需先用 `root.matches('#model-form')` 判断传入元素自身即表单，再向下查找，避免作用域查找返回 `null` 导致提交体为空。

## 五、视觉与响应式规范

- 风格基调：简洁高级、去 AI 味，参考主流 AI 产品；避免复杂外框装饰与卡片堆砌，主色为墨绿色系。
- 响应式断点：桌面端基准 1280px；移动端基准 390×844，全站无横向溢出。
- 图标统一使用内联 SVG（`AICONS` + `ico()`），品牌标识 `BRAND_MARK` 为 SVG 路径，前后台共用同一套绘制方式。
- 动效克制：仅状态过渡使用短过渡；遵循 `prefers-reduced-motion`。

## 六、测试约定

| 层级 | 命令 | 说明 |
| --- | --- | --- |
| Python 全量 | `python -m pytest` | 建议分批运行（Windows 下大批量偶发 `0xC0000005`），含 `test_admin_users.py`（用户管理生命周期/禁用拦截/权限）与注册双重密码校验用例 |
| 桌面端 UI | Playwright（1280×800） | 登录、注册（两次密码不一致提示）、模型设置弹窗、主题下拉、确认/输入弹窗、历史分析、后台三个板块（含用户管理增删禁用重置）、前后台侧边栏收缩展开与表单 |
| 移动端 UI | Playwright（390×844） | 抽屉导航、后台抽屉菜单、页面横向溢出断言（`scrollWidth <= clientWidth`） |

UI 冒烟的通用断言：主要页面遍历无 JS error、无横向溢出、精简后元素（`.nav-label`、`.sidebar-foot`、`.module-steps`）不存在、企业卡片存在。
