# FinBridge 融智 · 企业财务分析与融资决策

FinBridge（中文品牌「融智」）——面向一般非金融企业的原生网站。上传连续三年财务报表数据，提供外部净融资需求，完成财务分析、融资组合决策、风险检验与报告交付。规划期限固定为 **12个月**，资金用途固定为 **生产经营周转**。

**部署入口：`web_app.py`。运行依赖：`requirements-web.txt`。容器部署：使用根目录 `Dockerfile`。**

## 功能流程

分析工作台 → 企业与数据 → 财务分析 → 融资决策 → 风险评估 → 分析报告。

- **数据导入**：用户填写最新年度、上一年度、上两年度的年份及报表原值，金额展示统一为亿元；缺失数据不能以零代替。
- **财务分析**：计算指标，分块解释资产负债、应收与固定资产、营运资金、现金流和盈利变化。以前两年数据检验第三年现金预测误差，再对下一年预测作有限校正。
- **融资决策**：筛选信用、抵押、应收账款质押三类流动资金贷款。Python 混合整数规划先尽量覆盖净需求，再权衡一年成本与情景 CVaR，受现金、杠杆、产品容量及经营用途约束。
- **风险评估**：对固定组合检查六个明确情景，展示偿债安全线、缺口、逆向压力边界及 CVaR80% 的现金余量下降含义。
- **分析报告**：提炼财务结论、融资策略、风险与行动，下载 Word；专业对话携带本企业数据及分析背景，支持融资上限查询、多参数临时重算，采用前不改变正式结果。
- **历史分析**：每次执行的分析按项目留痕，可随时从「历史分析」恢复查看；「新融资分析」清空当前输入开始新项目；载入三个真实算例（海天、金山、宁沪高速）即自动生成一条完整分析，同一企业重复载入仅保留一条未复核记录。

AI 仅负责理解需求、选择工具和解释结果，数值由 Python 模型计算。模型接口可在页首「模型设置」中为当前账户配置自己的 OpenAI 兼容密钥（加密存储、仅显示掩码），未配置时依次使用平台托管与管理员配置、环境变量；对话区提供模型选择按钮，可一键切换生效模型。关闭 AI 仍可运行本地分析。行业地区资料只有经过检索核验才能作为近期证据。预测、融资比例、利率与压力参数含明确假设，结果不等于银行授信或未来现金承诺。

## 本地启动（Windows）

已有 Python 环境时，在项目根目录打开 PowerShell，执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\start-native.ps1
```

浏览器打开 `http://127.0.0.1:8787/`。首次安装依赖：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-web.txt
```

## 云端部署

建议 Python 3.12。在仓库根目录安装并启动：

```sh
python -m pip install -r requirements-web.txt
HOST=0.0.0.0 PORT=8000 python web_app.py
```

平台分配端口时使用平台的 `PORT`。支持 Docker 的平台直接选择根目录 `Dockerfile`，容器启动同一个原生入口。

已有 Docker Compose 网站更新：在服务器上的本仓库 `main` 分支目录执行 `bash deploy/update.sh`。脚本拉取最新代码、备份 SQLite、构建镜像、沿用现有 Compose 配置重建服务并检查启动；启动失败尝试恢复旧镜像。首次取得脚本及离线部署转接见 [服务器更新说明](deploy/deploy.md#从-github-一条命令更新现有网站)。

通过平台环境变量配置 `DEEPSEEK_API_KEY`、`BASE_URL`、`MODEL`，可选配置 `TAVILY_API_KEY`。变量示例见 `.env.example`；实际密钥不上传 GitHub。

**模型管理**：管理员设置 `ADMIN_PASSWORD` 后访问 `/admin.html` 维护平台托管密钥（编辑留空保留原值，连通性测试一键核验）；用户在页首「模型设置」为本会话添加自己的 OpenAI 兼容配置。所有调用按「用户自配 → 平台托管 → 环境变量」优先级解析，密钥以 Fernet 加密落库（主密钥可用 `FINBRIDGE_ENC_KEY` 指定，缺省自动生成）。

数据库通过 `FINBRIDGE_DB_PATH` 指定。容器默认使用 `/app/storage/runtime.sqlite3`，需要保留分析和对话时，将持久化磁盘挂载到 `/app/storage` 并另做备份。持久化存储不等于已经备份。

## 账户与角色

系统有两类账户，均为系统内注册产生，**没有预置的演示测试账号**：

| 角色 | 产生方式 | 权限 |
| --- | --- | --- |
| 管理员（admin） | 部署时设置环境变量 `ADMIN_PASSWORD`，首次启动自动播种用户名 `admin`、密码为该环境变量的管理员账号 | 登录 `/admin.html` 管理平台托管模型与全部托管密钥；在「用户管理」重置任意账户密码、禁用/启用/删除账户；无归属的历史分析在启动时自动归属管理员 |
| 普通用户 | 页面右上角「登录 / 注册」自行注册（需两次输入一致的新密码 + 图形验证码），未设 `ADMIN_PASSWORD` 时**首个注册用户自动成为管理员** | 使用全部分析功能；在「模型设置」添加自配模型密钥；历史分析按账户隔离，仅本人可见 |

- 注册时需两次输入一致的新密码（≥6 位）确认；忘记密码可联系管理员在后台「用户管理」中重置。
- 后台「用户管理」支持查看全部账户（含历史分析数量）、重置密码、禁用/启用与删除：禁用立即生效（登录接口与已签发 token 均拦截），删除会级联清理该账户的历史分析、自配模型与问答记录；管理员不能禁用或删除自己。
- `ADMIN_PASSWORD` 仅在首次播种 admin 账户时生效；admin 已存在后修改该变量不会改变已有密码，请通过后台「用户管理 → 重置密码」修改。
- 历史分析、对话与密钥均按账户隔离：同一浏览器会话登录不同账户，看到的历史分析会随账户合并；未登录的访客数据互相不可见。
- 测试体系中的账户（如 `tests/` 里的 `user01` / `secret123`）仅存在于 pytest 临时数据库，与部署实例无关，不构成任何真实账号。

## 测试

```powershell
# Python 全量（Windows 下建议分批运行，避免偶发崩溃）
python -m pytest tests/ -x
```

界面测试使用 Playwright 覆盖桌面端 1280×800 与移动端 390×844：登录注册、模型设置弹窗、主题化下拉与确认弹窗、历史分析抽屉、侧边栏折叠展开、决策对话（含模型选择）、后台侧边栏、移动端抽屉与横向溢出断言。约定与要点见 [docs/界面与管理后台.md](docs/界面与管理后台.md)。
